# Response fixtures

These are reconstructed, redacted API-shaped examples, not raw production captures. Cart numbers preserve the reported decimal-zero and fractional-discount failure (`0.0`, `62.2`, `1.8`). Identifiers, names, addresses, URLs and email addresses are synthetic; reserved example domains replace store/customer data. No credentials or checkout tokens are included.

- `cart.json`: v3 cart envelope, physical lines, discounts, nullable option values and unknown fields. Tests also exercise custom items, gift certificates and quoted monetary values.
- `cart-numeric-discount-ids.json`: the cart shape with synthetic numeric promotion IDs, including an integer beyond binary floating-point precision. Numeric IDs also appear in the official cart OpenAPI discount examples.
- `cart-promotions.json`: physical-item numeric and array coupons plus an object promotion banner, reconstructed from the official [cart OpenAPI](https://docs.bigcommerce.com/openapi/admin-management-carts.json).
- `modifiers.json`: a numeric modifier with fractional lower/upper bounds, reconstructed from the official [modifier OpenAPI](https://docs.bigcommerce.com/openapi/admin-catalog-product-modifiers.json).
- `checkout-urls.json`: cart redirect/embedded-checkout URLs, the checkout functionality currently exposed by this library. The library has no checkout resource model or CRUD endpoint; adding one is outside this fix.
- `order.json`: v2 unwrapped order, quoted and numeric money, RFC2822/ISO dates and empty shipment date.
- `product.json`: v3 catalog product, money and weight, optional fields and an unknown field.
- `customers.json`: v3 customer collection, quoted store credit and nullable dates/channel IDs.
- `order-transactions.json`: v3 order transaction page reconstructed from the official [orders v3 OpenAPI](https://github.com/bigcommerce/api-specs/blob/main/reference/orders.v3.yml) `Transaction` schema. It contains a successful authorization, a failed capture referencing it, and a transaction with future enum values, missing provider fields and an empty date. Gateway IDs, instrument tokens and card fields are placeholders; no card numbers or provider tokens are included.
- `order-refunds.json`: v3 order refund collection (`payment_actions/refunds`) reconstructed from the same OpenAPI `Refund`, `RefundItem` and `RefundPayment` schemas, including a declined refund payment, quoted and numeric money, a future item type and null/missing provider fields. The synthetic `declined_code` exercises a tolerated nullable extension absent from the published `RefundPayment` schema. Reasons and decline messages use synthetic values.

Schema references: [carts](https://github.com/bigcommerce/api-specs/blob/main/reference/carts.v3.yml), [orders v2](https://github.com/bigcommerce/api-specs/blob/main/reference/orders.v2.oas2.yml), [orders v3](https://github.com/bigcommerce/api-specs/blob/main/reference/orders.v3.yml), [products](https://github.com/bigcommerce/api-specs/blob/main/reference/catalog/products_catalog.v3.yml), [customers](https://github.com/bigcommerce/api-specs/blob/main/reference/customers.v3.yml), [pricing](https://github.com/bigcommerce/api-specs/blob/main/reference/pricing.sf.yml).
